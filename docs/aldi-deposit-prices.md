# ALDI Nord: published beverage prices and separate deposit

The collector can admit a current fixed sales-pack price with a positive deposit only when the original product response matches the reviewed ALDI Nord product-detail build. The native price and deposit remain separate; `payablePackPrice` adds the deposit once. The deposit value already represents the complete sales pack, including a multipack.

The public product rendering was inspected on 2 October 2026 at 23:12 UTC. COCA-COLA Original Taste, native SKU 4039, showed 1.59 EUR for a 1.25 l bottle plus 0.25 EUR deposit. QUELLBRUNN Classic, native SKU 1026202, showed 1.35 EUR for nine 0.5 l bottles plus 2.25 EUR deposit for the whole pack. These are dated evidence fixtures, not a production price fallback.

`aldi-deposit-render-contract.json` pins the observed immutable renderer files and their original response hashes. The audited code path is product-detail entry/config module 55056 → ProductCardDetail module 2308 → Tag module 45310. The native product-detail renderer passes the current price and formats the unmultiplied native `depositValue` alongside the native `zzgl. Pfand` label. Original public HTML and JavaScript response bytes are retained in `tests/fixtures/retailers/aldi-deposit/` for independent verification; none of that JavaScript is executed by Caddy.

`aldi-deposit-proof.js` derives a hash-bound attestation from each new original HTML response, binding the build, exact script paths, native product request/response identity, German product-detail template, separate-deposit label, sales pack, cents, capture time, and original response hash. This integrity hash is not a cryptographic signature; source authority comes from the collector's original public response and the reviewed renderer contract. A generic translation entry, a deposit flag, or a caller assertion cannot establish the price basis. A changed build, route, script or label holds positive-deposit prices until that renderer is reviewed. The check adds no native HTTP requests or price-freshness extensions.

The service independently revalidates the attestation before admission and on reads. PostgreSQL receives an additive JSONB proof column and migrates the historical zero-only deposit constraint to cent-valued positive deposit with a matching proof. Unknown and verified zero deposit remain supported. Original equal-capture hashes for historical zero/unknown rows are preserved; reprocessing cannot create a false conflict simply because the schema gained a field.

The existing bounds still apply: Germany, `assortment-publication`, unknown physical branch and availability, exact native sales pack, no attested GTIN, and no verified normal-price classification. A beverage price does not become a Berlin physical-store price. Native price validity and the original capture's maximum 24-hour freshness continue to limit every admitted quote. Source and per-article cooldowns and traversal checkpoints are preserved.
